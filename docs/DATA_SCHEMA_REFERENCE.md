# Data Schema Reference

This reference documents the record structures used by the pipeline:
measurement rows, request rows, the `ExtrapolationResult` model, and the
supporting enumerations. All field names are those actually written to
Excel and CSV outputs.

The authoritative source for `ExtrapolationResult` is
`src/string_technique_model/extrapolation/nonlinear/domain.py`.

## 1. Measurement rows (`Measured` sheet)

A measurement row describes one ordinary observation. Fields:

| Field | Type | Purpose |
|-------|------|---------|
| `note` | string | Scientific pitch notation (`C3`, `A#4`, …). |
| `midi` | int (optional) | MIDI number of `note` when resolvable. |
| `value` | float | Ordinary EWSD acoustic-balanced score. |
| `instrument` | string | `vln`, `vla`, `vlc`, or `cb`. |
| `dynamic` | string | `pp`, `mf`, or `ff`. |
| `technique` | string | Always `ordinary` for measurement rows. |
| `quantity` | string | Target quantity (default `EWSD_score_acoustic_balanced`). |
| `source_path` | string | Free-form provenance path (workbook, GUI, …). |
| `source_workbook_path` | string | Absolute path to the source workbook, when loaded from Excel. |
| `source_workbook_hash` | string | Truncated SHA-256 of the source workbook. |
| `source_sheet` | string | Sheet name (`Measured`). |
| `import_run_id` | string | Random 12-character import identifier. |
| `data_status` | enum | See below. |
| `scientific_use` | string | Free-form scientific-use policy. |

## 2. Request rows (`Requests` sheet)

A request row asks for a technique prediction at a specific note:

| Field | Type | Purpose |
|-------|------|---------|
| `note` | string | Requested sounding pitch (scientific pitch notation). |
| `technique` | string | One of `sul_tasto`, `sul_ponticello`, `con_sordino`, `artificial_harmonic`, `natural_harmonic`. |
| `instrument` | string | Instrument identifier. |
| `dynamic` | string | Dynamic identifier. |

Harmonic requests generated by the GUI additionally carry the sounding
geometry fields listed in section 5 below.

## 3. `data_status`

Defined on `ExtrapolationResult.data_status` (literal type). Allowed
values:

| Value | Meaning |
|-------|---------|
| `measured_real` | Recorded observation with a resolvable source path. |
| `measured_research_data` | Loaded from a workbook whose path and hash are stamped on the row. |
| `manual_register_entry` | Entered directly in the GUI without a workbook source. |
| `synthetic` | Generated for demonstration or documentation purposes. |
| `synthetic_integration_test` | Fixture data for tests. |
| `mixed` | Row aggregates rows of different statuses. |
| `unknown` | Provenance not established. |

## 4. `scientific_use`

Free-form string used to encode the doctoral-use policy. Values currently
emitted by the GUI:

| Value | Emitted when |
|-------|--------------|
| `allowed_with_workbook_provenance` | Row loaded from an Excel workbook. |
| `requires_source_workbook_for_doctoral_evidence` | Row entered manually in the GUI. |

## 5. Harmonic geometry fields

Harmonic requests and results carry additional geometry columns produced
by `src/string_technique_model/extrapolation/nonlinear/harmonic_register.py`:

| Field | Meaning |
|-------|---------|
| `harmonic_type` | `natural_harmonic` or `artificial_harmonic`. |
| `harmonic_order` | Integer harmonic order (`n`). |
| `string_name` | Open-string label (`G3`, `D4`, …). |
| `production_pitch` | Physical touching / stopping description. |
| `stopped_pitch` | Stopped pitch for artificial harmonics. |
| `touched_pitch` | Touched pitch for artificial harmonics. |
| `open_string_pitch` | Sounding pitch of the open string used. |
| `sounding_pitch` | Predicted sounding pitch (nearest tempered label). |
| `sounding_midi` | Integer MIDI of `sounding_pitch`. |
| `sounding_midi_float` | Fractional MIDI (from `n · f₀`). |
| `sounding_frequency_hz` | Sounding frequency in Hz. |
| `nearest_tempered_pitch` | Nearest equal-tempered label. |
| `cents_deviation` | Cents deviation from tempered pitch. |
| `target_range_min` / `target_range_max` | User-requested sounding range. |
| `within_harmonic_analysis_range` | Whether the target is inside the configured analysis range. |
| `within_ordinary_baseline_range` | Whether an ordinary baseline exists at that pitch. |
| `outside_ordinary_baseline_range` | Complement of the above. |
| `baseline_extrapolation_semitones` | Distance from the nearest baseline point. |
| `feasibility_status` | Feasibility label emitted by the generator. |
| `pitch_generation_method` | `open_string_times_order`, `artificial_from_touch_interval`, etc. |
| `target_status` | For example `included_by_physical_model` or `excluded_by_analysis_range`. |
| `baseline_support_policy` | Policy tag recorded for auditing. |
| `physical_range_min` / `physical_range_max` | Physical enumeration bounds. |
| `analysis_range_min` / `analysis_range_max` | Analysis-window bounds. |
| `included_by_physical_model` | Boolean gate. |
| `included_by_analysis_filter` | Boolean gate. |
| `excluded_reason` | Reason for exclusion, when applicable. |
| `selection_mode` | Selection mode used to enumerate the target. |
| `configuration_policy` | For example `canonical_single_string_assignment`. |
| `configured_order_min` / `configured_order_max` | Configured order bounds. |
| `order_selection_reason` | For example `practical_analysis_scope`. |

## 6. `EvidenceTier`

Defined in `EvidenceTier`. Values (ascending strength):

| Value | Meaning |
|-------|---------|
| `LEVEL_0_UNSUPPORTED` | No admissible evidence base. |
| `LEVEL_1_ASSUMPTION_ONLY` | Depends entirely on an activated assumption. |
| `LEVEL_1_BIBLIOGRAPHIC_QUALITATIVE` | Bibliographic qualitative claim. |
| `LEVEL_2_METADATA_CONSTRAINED` | Constrained by metadata (for example a harmonic geometry). |
| `LEVEL_3_PARTIAL_EMPIRICAL` | Partial empirical evidence in the local corpus. |
| `LEVEL_4_MATCHED_EMPIRICAL` | Fully matched empirical evidence. |

## 7. `ValueKind`

Defined in `ValueKind`. Values:

| Value | Meaning |
|-------|---------|
| `measured` | Recorded ordinary observation. |
| `derived_from_measured` | Deterministic transformation of measurements. |
| `extrapolated` | Predicted from a fitted or hierarchical submodel. |
| `approximate_from_penalized_fit` | Interval computed from a penalized fit approximation. |
| `assumption_based_extrapolation` | Value depends on an activated user assumption. |
| `qualitative_only` | Qualitative tendency only. |
| `unavailable` | Neither numerical nor qualitative estimate. |

## 8. `ConvergenceStatus`

Values: `converged`, `approximate_frequentist`, `diverged`,
`not_applicable`, `backend_unavailable`.

## 9. `SensitivityStatus`

Values: `stable`, `prior_sensitive`, `data_limited`,
`outside_baseline_range`, `not_evaluated`.

## 10. `ExtrapolationResult` — key fields

For brevity, the table groups fields into logical sections. The complete
schema is available in
`src/string_technique_model/extrapolation/nonlinear/domain.py`.

### Identity and target

| Field | Purpose |
|-------|---------|
| `record_id` | Random 12-character result identifier. |
| `instrument`, `technique`, `dynamic`, `pitch`, `midi` | Cell coordinates. |
| `target_quantity` | Requested quantity name. |
| `unit` | Unit label. |

### Neutral estimate fields

| Field | Purpose |
|-------|---------|
| `estimate_mean` | Preferred mean estimate. |
| `estimate_median` | Preferred median estimate. |
| `estimate_sd` | Preferred standard deviation. |
| `interval_low`, `interval_high` | Preferred interval bounds. |
| `interval_type` | `assumption_distribution_interval`, `approximate_interval_from_penalized_fit`, or a Bayesian type. |
| `interval_formula` | Free-form description of the interval derivation. |
| `interval_kind` | Legacy alias kept for backwards compatibility. |

### Bayesian-only fields (only meaningful when `bayesian_backend_used=True`)

`posterior_mean`, `posterior_median`, `posterior_sd`,
`credible_interval_low`, `credible_interval_high`,
`credible_interval_probability`, `log_ratio_mean`, `log_ratio_sd`,
`probability_above_ordinary`. When the Bayesian backend was **not** used
these fields are cleared on export.

### Technique effect

| Field | Purpose |
|-------|---------|
| `technique_multiplier` | Multiplicative effect on the baseline. |
| `alpha_t` | Log-ratio coefficient. |
| `alpha_origin` | `regularization_assumption`, `user_assumption`, `evidence_only`, etc. |
| `effect_kind` | Free-form label. |
| `qualitative_effect_vs_ordinary` | Direction (`increases`, `decreases`, `mixed`, `unclear`). |
| `attenuation_db_power` | Only for mute rows; recorded as an audit label. |

### Baseline provenance

| Field | Purpose |
|-------|---------|
| `baseline_value` | Ordinary baseline evaluated at the requested pitch. |
| `baseline_record_ids` | Identifiers of the source rows. |
| `baseline_n_observations`, `baseline_midi_min`, `baseline_midi_max`, `baseline_penalty_lambda`, `baseline_spline_degree`, `baseline_n_knots` | Spline fit diagnostics. |

### Model selection

| Field | Purpose |
|-------|---------|
| `model_id`, `submodel_id`, `model_version` | Model identity. |
| `model_family`, `mechanism` | Family descriptors. |
| `selected_model_id`, `selection_reason`, `fallback_level` | Selection outcome. |
| `candidate_model_ids`, `rejected_model_ids`, `rejection_reasons` | Full audit trail. |
| `complexity_level` | Rung of the ladder. |
| `model_selection_status` | Coarse status label. |
| `distinct_pitch_count`, `pitch_span_semitones`, `target_technique_observations` | Data availability summary. |

### Covariates and model components

| Field | Purpose |
|-------|---------|
| `required_covariates` | Covariates required for the selected family. |
| `available_covariates` | Covariates found in the data. |
| `missing_covariates` | Difference of the two lists above (raw covariate gaps). |
| `missing_model_components` | Model components (not covariates) that must be registered before numeric extrapolation. |
| `modal_metadata_status` | For harmonics: `complete`, `incomplete`, or `unknown`. |
| `acoustic_calibration_status` | For harmonics: `calibrated`, `unavailable`, or `unknown`. |

The distinction between `missing_covariates` and
`missing_model_components` is significant: covariates are input fields
present or absent on the data; model components are back-end capabilities
(for example a calibrated harmonic descriptor model) that must be
registered before numeric extrapolation.

### Assumptions and priors

| Field | Purpose |
|-------|---------|
| `assumption_ids` | Only identifiers matching `ASSUMP_*`. |
| `assumptions_trace` | Free-form audit trail. |
| `assumptions_used` | Deprecated alias mapped to `assumption_ids` on export. |
| `prior_ids` | Priors consumed by the fit. |
| `source_ids`, `source_pages` | Literature source references. |

### Provenance

| Field | Purpose |
|-------|---------|
| `data_status`, `scientific_use` | Provenance policy. |
| `source_workbook_path`, `source_workbook_hash`, `source_sheet`, `import_run_id`, `source_row_ids` | Origin of the row. |

### Diagnostics

| Field | Purpose |
|-------|---------|
| `sigma_origin`, `sigma_value`, `sigma_estimated_from_data` | Residual scale metadata. |
| `register_shape_identified`, `shape_source`, `g_t_active` | Register-curve identifiability. |
| `prior_dominated` | Whether the fit is dominated by the prior. |
| `evidence_tier`, `measured_or_extrapolated`, `value_kind` | Confidence labels. |
| `warnings`, `calculation_trace` | Free-form audit lists. |
| `diagnostics_status`, `convergence_status`, `sensitivity_status` | Enum diagnostics. |
| `probability_above_ordinary`, `assumption_probability_above_ordinary` | Optional probabilistic summaries. |
| `model_status`, `na_reason` | Coarse status and refusal reason. |

## 11. `to_row()` behaviour

`ExtrapolationResult.to_row()` prepares a dictionary that mirrors the
Excel-friendly row layout. It:

- Copies `posterior_*` into the neutral `estimate_*` columns when the
  neutral columns are empty.
- Filters `assumption_ids` to `ASSUMP_*` and populates
  `assumptions_trace` from the residual free-form entries.
- Joins list fields (`baseline_record_ids`, `prior_ids`, …) with `;`.
- Replaces `None` in Boolean gate fields with the string
  `not_applicable`.
- Sets `extrapolation_method` to `selected_model_id or model_id`.
- Clears the Bayesian-only columns when `bayesian_backend_used=False`.

Downstream consumers should read the neutral columns
(`estimate_mean`, `estimate_median`, `estimate_sd`, `interval_low`,
`interval_high`) unless a Bayesian workflow was explicitly enabled.
